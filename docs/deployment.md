# النشر على GitHub Pages + Supabase

كل ما يلي مجاني بالكامل ولا يحتاج بطاقة. الوقت المتوقع: نصف ساعة تقريبًا.

**الخلاصة:** GitHub Pages يقدّم ملفات الموقع، وSupabase يحمل قاعدة البيانات
والصور وتسجيل الدخول. لا يوجد سيرفر بينهما، ولا شيء «ينام» ولا يحتاج ping.

> ⚠️ **قبل أن تبدأ — ملاحظة على شروط GitHub Pages**
> شروط GitHub تنص على أن Pages مخصّص لصفحات شخصية ومشاريع مفتوحة المصدر،
> وأنه ليس للاستضافة التجارية (متجر إلكتروني، خدمة تجارية…). موقع تعريفي بورشتك
> يميل إلى المنطقة الرمادية، وموقع يبيع خدمات لا. لن يوقفه أحد غالبًا، لكن اعرف
> أن ذلك ممكن ولا يوجد التزام تجاه حسابك.
> لو أردت أساسًا أمتن ومجانيًا أيضًا: **Netlify** يسمح بالاستخدام التجاري صراحةً،
> وينشر نفس المشروع تمامًا بلا تعديل (ملف `netlify.toml` كل ما يلزم).
> وعند شراء VPS ودومين تعود إلى النسخة الأصلية في مجلد `elmagd 2`.

---

## 1) إنشاء مشروع Supabase

1. افتح [supabase.com](https://supabase.com) → **Start your project** → سجّل بحساب GitHub.
2. **New project**:
   - **Name:** `elmagd`
   - **Database Password:** كلمة سر قوية — احفظها في مكان آمن.
   - **Region:** `Central EU (Frankfurt)` — الأقرب لمصر.
3. انتظر دقيقتين حتى يجهز المشروع.

**الحدود المجانية:** 500 ميجابايت قاعدة بيانات، 1 جيجابايت تخزين، 5 جيجابايت نقل شهريًا.
كافية جدًا لموقع بهذا الحجم.

> المشروع المجاني يتوقف بعد **أسبوع كامل بلا أي زيارة**، ويعود بضغطة واحدة من
> لوحة Supabase. زيارة واحدة أسبوعيًا تكفي لإبقائه شغّالًا.

---

## 2) بناء قاعدة البيانات

في لوحة Supabase → **SQL Editor** → **New query**:

1. الصق محتوى `supabase/schema.sql` كاملًا → **Run**.
2. **New query** مرة أخرى، والصق محتوى `supabase/seed.sql` → **Run**.

هذا ينشئ الجداول وسياسات الحماية ودالة التسعير، ويزرع محتوى الموقع الافتراضي.

**تأكّد أن بريدك مكتوب صحيحًا:**

```sql
select public.owner_email();
```

يجب أن يعيد `masry5357@gmail.com`. لتغييره لاحقًا عدّل الدالة في أعلى
`supabase/schema.sql` وأعد تشغيل ذلك الجزء وحده.

---

## 3) إنشاء حسابك أنت — وإغلاق الباب خلفك

1. **Authentication → Users → Add user → Create new user**
   - **Email:** `masry5357@gmail.com`
   - **Password:** كلمة السر التي تريدها للوحة التحكم
   - فعّل **Auto Confirm User** حتى لا تنتظر رسالة تأكيد.

2. **Authentication → Sign In / Providers → Email**، وأغلق
   **Allow new users to sign up**.

الخطوة الثانية مهمة: بها يصبح حسابك هو الحساب الوحيد الذي يمكن أن يوجد أصلًا.
حتى لو تُرك التسجيل مفتوحًا فلن يستطيع أي حساب آخر قراءة طلب أو تعديل محتوى —
لكن إغلاقه يمنع حتى المحاولة.

---

## 4) إنشاء حاوية الصور

أنشأها `schema.sql` تلقائيًا. للتأكد: **Storage** → يجب أن ترى حاوية اسمها
`media` بعلامة **Public**. لو لم تكن موجودة، أنشئها بنفس الاسم واجعلها عامة.

---

## 5) نسخ المفاتيح

**Project Settings → API**، وانسخ:

| المفتاح | أين يُستخدم |
| --- | --- |
| **Project URL** | `NEXT_PUBLIC_SUPABASE_URL` |
| **anon / publishable key** | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |

> **لا تنسخ `service_role` ولا تضعه في أي مكان في المشروع.** هذا المفتاح
> يتجاوز كل سياسات الحماية، ووضعه في موقع ثابت يعني تسليم القاعدة كاملة لأي زائر.
> المفتاحان أعلاه عامان بطبيعتهما وظهورهما في كود الصفحة أمر طبيعي ومقصود.

---

## 6) رفع المشروع على GitHub

> **خطوة صغيرة أولًا:** انقل ملف النشر إلى مكانه.
> لم يُكتب مباشرة داخل `.github/workflows` لأن الأدوات تمنع الكتابة هناك عن بُعد.
>
> ```powershell
> cd "E:\elmagd_githap"
> mkdir .github\workflows
> move docs\deploy-workflow.yml .github\workflows\deploy.yml
> ```

```bash
cd "E:\elmagd_githap"

git init
git add .
git commit -m "3D Elmagd — نسخة GitHub Pages + Supabase"
git branch -M main
git remote add origin https://github.com/<حسابك>/<اسم-المستودع>.git
git push -u origin main
```

المستودع يمكن أن يكون **Private**؛ GitHub Pages يعمل مع المستودعات الخاصة أيضًا.

---

## 7) ضبط أسرار المستودع وتشغيل Pages

**Settings → Secrets and variables → Actions → New repository secret**، وأضِف:

| الاسم | القيمة |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL من الخطوة 5 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key من الخطوة 5 |

وفي تبويب **Variables** بنفس الصفحة:

| الاسم | القيمة |
| --- | --- |
| `OWNER_EMAIL` | `masry5357@gmail.com` |

ثم **Settings → Pages → Build and deployment → Source: GitHub Actions**.

الآن **Actions → نشر الموقع على GitHub Pages → Run workflow** (أو ادفع أي تعديل).
الملف يفحص الأنواع ويشغّل الاختبارات ثم يبني وينشر. الرابط يظهر في نهاية التشغيل:

```
https://<حسابك>.github.io/<اسم-المستودع>/
```

> **مسار الموقع يُضبط تلقائيًا.** لو استخدمت نطاقًا خاصًا لاحقًا، أضِف متغيّر
> `SITE_BASE_PATH` بقيمة `none` حتى يبني الموقع على جذر النطاق.

---

## 8) الخطوة الأخيرة — اربط الموقع بـ Supabase

عُد إلى Supabase → **Authentication → URL Configuration**:

- **Site URL:** رابط موقعك من الخطوة السابقة.
- **Redirect URLs:** أضِف نفس الرابط، وأضِف `http://localhost:3000/**` للتطوير المحلي.

بدون هذه الخطوة يعمل الموقع لكن قد تفشل بعض عمليات الدخول.

---

## اختبار سريع بعد النشر

| ما تختبره | المتوقع |
| --- | --- |
| افتح الموقع | يظهر بالمحتوى الذي زرعته من `seed.sql` |
| افتح `/login` وادخل ببريدك وكلمة سرك | تنتقل إلى `/admin/orders` |
| عدّل اسم البراند من تبويب الهوية | يتغيّر في الهيدر فورًا، ويبقى بعد إعادة التحميل |
| ارفع صورة عمل من تبويب المعرض | تظهر الصورة (وتُخزَّن في Supabase Storage) |
| املأ نموذج التواصل من نافذة تصفّح خفي | يفتح واتساب، ويظهر الطلب في لوحتك |
| افتح `/admin` من نافذة خفية بلا دخول | تُحوَّل إلى صفحة الدخول ولا ترى شيئًا |

## الصيانة

- **أي تعديل في الكود:** `git push` والنشر يتم تلقائيًا خلال دقيقتين.
- **نسخة احتياطية من المحتوى:** لوحة التحكم → «النسخ والاستعادة» → تصدير JSON.
- **نسخة احتياطية من القاعدة:** Supabase → Database → Backups.
- **إبقاء المشروع نشطًا:** افتح الموقع مرة أسبوعيًا على الأقل.

## فحص الحماية بنفسك (اختياري)

لو أردت التأكد من سياسات الحماية على قاعدة PostgreSQL محلية:

```bash
psql -d elmagd_test -f supabase/tests/local-stubs.sql   # محاكاة مخططات Supabase
psql -d elmagd_test -f supabase/schema.sql
psql -d elmagd_test -f supabase/seed.sql
psql -d elmagd_test -f supabase/tests/rls-test.sql      # محاولات وصول مرفوضة ومسموحة
```

الملف الأخير يحاول عمدًا: الكتابة كزائر، قراءة الطلبات كعميل مسجّل، الإدراج المباشر
في جدول الطلبات، ورفع صورة بلا صلاحية — ويجب أن تُرفض كلها.
